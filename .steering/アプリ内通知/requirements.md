# 要求内容: アプリ内通知

## 概要

チームメンバーが自分に関係するタスクの変化（担当割り当て・期限超過）をアプリ内で受け取れる通知機能を実装する。外部連携なし・アプリ内完結。

## 背景

`docs/functional-design.md` にて `NotificationsController` と `NotificationService` が「未実装」と記載されており、担当者割り当て時の通知送信も `TaskService` に未統合の状態。また `Notification` エンティティと `NotificationType` 列挙型はドキュメント上で定義済みだが、コード上に存在しない。

## 実装対象の機能

### 1. 担当割り当て通知
- タスクに担当者が追加された際、その担当者に通知を生成する
- `POST /api/tasks/{id}/assignees` 経由での追加時に自動トリガー
- `CreateTask` 時の `AssigneeIds` 一括登録時にも通知を生成する

### 2. 期限超過通知（Hangfire バックグラウンドジョブ）
- 毎日 00:05 に期限超過タスクの担当者へ通知を生成する
- 当日すでに通知済みのタスクは重複生成しない
- 「完了」ステータスのタスクは対象外

### 3. 通知一覧 API
- ログインユーザー自身の通知一覧を取得する（最新順）
- 未読件数を含むレスポンスを返す
- 個別既読・全件既読の更新 API を提供する

### 4. 通知ベルUI（フロントエンド）
- ヘッダー/ナビゲーション部に通知ベルアイコンを表示する
- 未読件数バッジを表示する（0件の場合はバッジ非表示）
- 30秒ポーリングで未読件数を自動更新する
- ベルアイコンクリックで通知一覧ページへ遷移する

### 5. 通知一覧ページ（フロントエンド）
- 通知の一覧を表示する（タイプ・メッセージ・日時）
- 未読通知を視覚的に強調表示する
- 「すべて既読にする」ボタンを提供する
- 通知に関連タスクがある場合はタスク詳細へのリンクを表示する

## 受け入れ条件

### 担当割り当て通知
- [ ] タスク作成時に AssigneeIds が指定された場合、各担当者に Assigned 通知が生成される
- [ ] POST /api/tasks/{id}/assignees で担当者追加時に Assigned 通知が生成される
- [ ] 通知メッセージは「「{タスクタイトル}」の担当者に追加されました」形式である

### 期限超過通知
- [ ] Hangfire ジョブが 00:05 に実行される
- [ ] 期限日が前日以前・完了ステータス以外のタスク担当者に Overdue 通知が生成される
- [ ] 当日すでに Overdue 通知が送られた担当者にはスキップされる
- [ ] 通知メッセージは「「{タスクタイトル}」の期限が超過しています」形式である

### 通知 API
- [ ] GET /api/notifications でログインユーザーの通知一覧と未読件数が返る
- [ ] PUT /api/notifications/{id}/read で個別既読処理ができる
- [ ] PUT /api/notifications/read-all で全件既読処理ができる
- [ ] 他ユーザーの通知には 403 Forbidden が返る

### フロントエンド
- [ ] Shell コンポーネントに通知ベルが表示され、未読件数バッジが表示される
- [ ] 通知一覧ページ（/notifications）で通知の一覧が表示される
- [ ] 未読通知が視覚的に強調される
- [ ] 「すべて既読にする」ボタンで全件既読になる

## スコープ外

以下はこのフェーズでは実装しません:

- メール・Slack等の外部通知連携
- リアルタイムプッシュ通知（WebSocket/SignalR）
- 通知の削除機能
- 通知設定（通知の種類を個人ごとにON/OFFする機能）
