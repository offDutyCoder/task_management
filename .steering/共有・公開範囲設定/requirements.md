# 要求内容

## 概要

タスクの共有・公開範囲設定機能を実装する。タスク詳細画面での共有ユーザーの表示・追加・削除と、バックエンドAPIエンドポイントの整備を行う。

## 背景

PRD「機能6: タスクの共有・公開範囲設定」はP0（必須）として定義されており、既にバックエンドの基盤（TaskShareエンティティ、サービスロジック、リポジトリのアクセス制御）は実装済み。ただし以下のギャップが存在する：

- `TaskDetailResponse` が `ShareUserIds: List<int>` のみを返しており、表示名が含まれていない
- タスク詳細画面（task-detail）に共有ユーザーのセクションが存在しない
- 担当者（assignee）パターンのような「個別追加・削除」APIエンドポイントが共有ユーザーには存在しない

## 実装対象の機能

### 1. バックエンド: 共有ユーザー個別操作API

- `POST /api/tasks/{id}/shares` で共有ユーザーを1人追加できる
- `DELETE /api/tasks/{id}/shares/{userId}` で共有ユーザーを1人削除できる
- `TaskDetailResponse.ShareUserIds: List<int>` を `ShareUsers: List<AssigneeDto>` に変更して表示名を返す

### 2. フロントエンド: タスク詳細画面での共有ユーザー表示・操作

- タスク詳細画面（meta-card）に「共有ユーザー」セクションを表示する
- 各共有ユーザーの表示名を一覧表示し、削除ボタンを提供する
- ユーザー追加ダイアログを介して共有ユーザーを追加できる（担当者追加UIを流用）

### 3. バックエンド: ユニットテスト追加

- `AddShareUserAsync` / `RemoveShareUserAsync` のビジネスルール（作成者保護・重複防止等）を検証するユニットテストを追加する

## 受け入れ条件

### タスク作成・編集フォーム
- [ ] タスク作成/編集ダイアログで共有ユーザーを複数選択できる（既存UIは維持）
- [ ] 選択されなかった場合は作成者のみが共有ユーザーになる
- [ ] 作成者が選択されていなくても自動的に追加される

### タスク詳細画面
- [ ] 詳細画面のメタ情報欄に「共有ユーザー」セクションが表示される
- [ ] 共有ユーザーの表示名が一覧表示される
- [ ] 各共有ユーザーの横に削除ボタンがある（担当者セクションと同様のUI）
- [ ] 追加ボタンでユーザー選択ダイアログを開き、共有ユーザーを追加できる
- [ ] 0人の場合は「未設定」と表示される

### サブタスクでの表示
- [ ] サブタスクの詳細画面では「親タスクの設定を継承」と表示される（自分のSharesレコードを持たないため）

### バックエンドAPIの追加
- [ ] `POST /api/tasks/{id}/shares { userId }` で共有ユーザーが追加できる
- [ ] `DELETE /api/tasks/{id}/shares/{userId}` で共有ユーザーが削除できる
- [ ] 作成者を共有ユーザーから削除しようとした場合は 403 Forbidden を返す
- [ ] 既に共有済みのユーザーを追加しようとした場合は 409 Conflict を返す
- [ ] `GET /api/tasks/{id}` のレスポンスに `shareUsers: [{id, displayName}]` が含まれる

### アクセス制御
- [ ] 共有範囲外のユーザーはタスクを閲覧できない（既存ロジックを維持）
- [ ] サブタスクは親タスクの共有設定を自動継承する（既存ロジックを維持）

## スコープ外

以下はこのフェーズでは実装しません:

- 部署・グループ単位の共有設定（Post-MVP）
- サブタスクへの個別共有設定
- 共有ユーザー変更時の通知
