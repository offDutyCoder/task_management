# プロジェクト用語集 (Glossary)

## 概要

このドキュメントは、TaskApp プロジェクト内で使用される用語の定義を管理します。

**更新日**: 2026-05-03

---

## ドメイン用語

### タスク

**定義**: ユーザーが完了すべき作業の単位。

**説明**: タスクはシステムの中心的なエンティティで、タイトル（必須）・ステータス（必須）・担当者・期限・優先度・ラベル・説明などの属性を持つ。通常タスクと定期タスクの2種類がある。

**関連用語**:
- [サブタスク](#サブタスク): タスクの配下に作成される子タスク
- [定期タスク](#定期タスク): テンプレートから自動生成される繰り返しタスク
- [ステータス](#ステータス): タスクの進行状態

**使用例**:
- 「タスクを登録する」: 新しいタスクをシステムに作成する
- 「タスクを割り当てる」: タスクの担当者を設定する

**英語表記**: Task

---

### サブタスク

**定義**: 既存のタスク（親タスク）の配下に作成される子タスク。

**説明**: タスクは階層的なツリー構造を持つ。サブタスクは親タスクの公開範囲を自動継承するため、個別に共有設定を行う必要がない。チェックリスト形式でサブタスクの進捗を管理することで、親タスク全体の進捗を把握できる。

**関連用語**:
- [タスク](#タスク): サブタスクの親となるエンティティ
- [公開範囲](#公開範囲): 親タスクから継承される閲覧権限

**使用例**:
- 「サブタスクを追加する」: 既存タスクの配下に子タスクを作成する

**英語表記**: Subtask / Child Task

---

### ステータス

**定義**: タスクの現在の進行状態を示す管理者定義のマスタデータ。

**説明**: ステータスはアプリ全体で共通のものを管理者が定義する。デフォルトは「未着手・進行中・レビュー中・保留・完了」の5種類。各ステータスには名前・表示順・バッジ色が設定される。将来的にはプロジェクト単位のカスタマイズに拡張予定（現在はスコープ外）。

**初期定義**:

| ステータス名 | 色 | 意味 |
|---|---|---|
| 未着手 | グレー | タスクがまだ開始されていない |
| 進行中 | 青 | 担当者が作業に取り組んでいる |
| レビュー中 | オレンジ | 作業完了後に承認待ちの状態 |
| 保留 | 赤 | 何らかの理由でタスクが止まっている |
| 完了 | 緑 | タスクが完了した |

**関連用語**:
- [タスク](#タスク): ステータスを持つエンティティ
- [優先度](#優先度): ステータスとは独立した別軸の属性

**英語表記**: Status / Task Status

---

### 優先度

**定義**: タスクの重要度・緊急度を示す3段階の指標。

**説明**: タスク作成時にオプションで設定できる属性。デフォルト値は「中」。

**取りうる値**:

| 値 | 意味 | バッジ色 |
|---|---|---|
| 高 | 緊急かつ重要。速やかな対応が必要 | 赤 |
| 中 | 重要だが緊急ではない（デフォルト） | 橙 |
| 低 | 重要度・緊急度ともに低い | 青 |

**関連用語**:
- [タスク](#タスク): 優先度を持つエンティティ

**英語表記**: Priority

---

### ラベル / タグ

**定義**: タスクをカテゴリ分けするためのキーワード。管理者が定義・管理する公式タグ。

**説明**: ラベルはタグの表記ゆれや重複を防ぐため、管理者のみが作成・編集できる。ユーザーはタスクに公式ラベルの中から選んで付与する。新しいラベルが必要な場合、ユーザーは管理者に[ラベルリクエスト](#ラベルリクエスト)を送ることができる。

**関連用語**:
- [ラベルリクエスト](#ラベルリクエスト): ユーザーが新しいラベルを管理者に申請する機能

**英語表記**: Label / Tag

---

### ラベルリクエスト

**定義**: ユーザーが管理者に対して新しいラベルの追加を申請する機能・レコード。

**説明**: ユーザーは公式ラベルの中から選んでしか使えないため、新しい分類が必要な場合はリクエストを通じて管理者に申請する。管理者はリクエストを承認または却下できる。

**状態遷移**:

| 状態 | 意味 |
|---|---|
| 申請中（Pending） | ユーザーがリクエストを送信した |
| 承認済み（Approved） | 管理者がラベルを作成した |
| 却下（Rejected） | 管理者がリクエストを却下した |

**関連用語**:
- [ラベル / タグ](#ラベル--タグ): リクエストの対象

**英語表記**: Label Request

---

### 担当者

**定義**: タスクの実施責任を持つユーザー。1タスクに複数人割り当て可能。

**説明**: タスクへの担当者割り当て時にアプリ内通知が送られる。担当者は自分のタスクをダッシュボードの「マイタスク」で確認できる。他のユーザーへのタスク振り分け・引き取りも可能。

**関連用語**:
- [マイタスク](#マイタスク): 担当者として割り当てられたタスクの一覧

**英語表記**: Assignee

---

### 公開範囲

**定義**: タスクを閲覧できるユーザーの範囲。タスク単位で設定する。

**説明**: タスク作成時に共有するメンバーを個人単位で選択する。サブタスクは親タスクの公開範囲を自動継承するため、毎回設定する必要がない。公開範囲外のユーザーは API レベルでアクセスが拒否される。将来的には部署・グループ単位の共有設定に拡張予定（現在はスコープ外）。

**関連用語**:
- [サブタスク](#サブタスク): 親タスクの公開範囲を継承するエンティティ

**英語表記**: Share / Visibility / Access Scope

---

### 定期タスク

**定義**: [定期タスクテンプレート](#定期タスクテンプレート)から自動生成される繰り返しタスク。

**説明**: 日常業務（掃除・点検など）を毎回手動登録しなくて済むよう、バックグラウンドジョブが設定した時刻にテンプレートからタスクを自動生成する。タスク一覧・ダッシュボードではデフォルト非表示で、フィルターで表示を切り替えられる。

**関連用語**:
- [定期タスクテンプレート](#定期タスクテンプレート): 定期タスクの元となるテンプレート
- [バックグラウンドジョブ](#バックグラウンドジョブ): 定期タスクを自動生成する仕組み

**英語表記**: Recurring Task

---

### 定期タスクテンプレート

**定義**: 定期タスクを自動生成するための設定情報（タイトル・担当者・スケジュール等）を保持するマスタデータ。

**説明**: 管理者が作成・管理する。テンプレートに保存される情報はタイトル・説明・担当者・優先度・ラベル・共有設定。繰り返し頻度（毎日/毎週◯曜日/毎月◯日）と除外日（土日・祝日）を設定できる。

**繰り返し頻度の種類**:
- 毎日（Daily）
- 毎週◯曜日（Weekly）
- 毎月◯日（Monthly）

**関連用語**:
- [定期タスク](#定期タスク): テンプレートから生成されるタスク

**英語表記**: Recurring Template

---

### マイタスク

**定義**: ダッシュボードに表示される、現在ログイン中のユーザーが担当者として割り当てられているタスクの一覧。

**説明**: ダッシュボードの最優先エリアに表示される。期限超過のタスクは視覚的に区別して表示される。

**関連用語**:
- [ダッシュボード](#ダッシュボード): マイタスクが表示される画面

**英語表記**: My Tasks

---

### チーム共有タスク

**定義**: ダッシュボードに表示される、現在ログイン中のユーザーが閲覧権限を持つタスクの一覧（チーム全体の作業状況を把握するための表示）。

**説明**: 誰が何のタスクを担当・消化中かをひと目で把握できる。公開範囲の設定により、閲覧できるタスクはユーザーによって異なる。

**関連用語**:
- [ダッシュボード](#ダッシュボード): チーム共有タスクが表示される画面
- [公開範囲](#公開範囲): 閲覧できるタスクを制限する設定

**英語表記**: Team Shared Tasks

---

### ダッシュボード

**定義**: ログイン後の初期画面。「マイタスク」と「チーム共有タスク」を一覧表示する。

**説明**: ユーザーが毎朝ここを確認することで、自分の担当タスクとチームの作業状況を素早く把握できるよう設計されている。

**関連用語**:
- [マイタスク](#マイタスク)
- [チーム共有タスク](#チーム共有タスク)

**英語表記**: Dashboard

---

### 通知

**定義**: アプリ内で発生するイベントをユーザーに知らせる機能。

**説明**: アプリ内通知のみ対応（メール・Slack 連携はスコープ外）。通知が発生するイベントは「タスクへの担当者割り当て」「担当タスクの期限超過」の2種類。

**通知種別**:

| 種別 | トリガー |
|---|---|
| 担当割り当て（Assigned） | 自分がタスクの担当者として追加された |
| 期限超過（Overdue） | 担当タスクの期限日を過ぎた |

**英語表記**: Notification

---

## 技術用語

### ASP.NET Core

**定義**: Microsoft が提供するオープンソースのクロスプラットフォーム Web フレームワーク（C# で実装）。

**本プロジェクトでの用途**: バックエンド Web API の実装、Cookie 認証、ミドルウェア構成に使用。

**バージョン**: .NET 8 LTS

**関連ドキュメント**: [アーキテクチャ設計書](./architecture.md)

---

### Angular

**定義**: Google が開発するオープンソースの SPA フレームワーク（TypeScript で実装）。

**本プロジェクトでの用途**: フロントエンドの UI 実装全般。コンポーネントベースで画面を構成し、Angular Material で UI を統一。

**バージョン**: 17.x

**関連ドキュメント**: [アーキテクチャ設計書](./architecture.md)

---

### Angular Material

**定義**: Angular 向けのマテリアルデザイン UI コンポーネントライブラリ。

**本プロジェクトでの用途**: ボタン・テーブル・フォーム・バッジ等の UI コンポーネント全般。デザインの統一とアクセシビリティ対応のために採用。

**バージョン**: 17.x（Angular と同期）

---

### Entity Framework Core（EF Core）

**定義**: .NET 向けのオープンソース ORM（Object-Relational Mapper）。

**本プロジェクトでの用途**: SQL Server へのデータアクセス・LINQ クエリ・マイグレーション管理に使用。パラメータバインディングにより SQLインジェクションを防止。

**バージョン**: 8.x

---

### Hangfire

**定義**: .NET 向けのバックグラウンドジョブ処理ライブラリ。管理 UI が標準搭載。

**本プロジェクトでの用途**: 定期タスクの自動生成ジョブと期限超過通知ジョブの実行スケジューリングに使用。ジョブの状態は SQL Server に永続化される。

**バージョン**: 1.8.x

**関連用語**:
- [バックグラウンドジョブ](#バックグラウンドジョブ)
- [定期タスク](#定期タスク)

---

### SQL Server

**定義**: Microsoft が提供するリレーショナルデータベース管理システム（RDBMS）。

**本プロジェクトでの用途**: 業務データ（タスク・ユーザー等）および Hangfire ジョブ情報の永続化。

**バージョン**: 2019 以上

---

### IIS（Internet Information Services）

**定義**: Windows Server 付属の Web サーバー・リバースプロキシサービス。

**本プロジェクトでの用途**: Angular SPA の静的ファイル配信と ASP.NET Core API へのリバースプロキシとして使用。SSL 終端もここで行う。

---

## アーキテクチャ用語

### レイヤードアーキテクチャ

**定義**: システムを役割ごとに複数の層に分割し、上位層から下位層への一方向の依存関係を持たせる設計パターン。

**本プロジェクトでの適用**:

```
Controller（HTTPリクエスト受付・レスポンス）
    ↓
Service（ビジネスロジック）
    ↓
Repository（SQL Serverアクセス）
```

**メリット**:
- 各層の責務が明確で保守しやすい
- 層ごとに独立してテスト可能（Repository をモック化してService をテストできる）
- 変更の影響範囲が限定的

**依存ルール**:
- Controller → Infrastructure への直接参照禁止（DI 経由のみ）
- Service → Controller への依存禁止
- Repository → Service への依存禁止

**関連ドキュメント**: [アーキテクチャ設計書](./architecture.md)

---

### バックグラウンドジョブ

**定義**: HTTP リクエストとは独立して、バックグラウンドで非同期に実行される処理。

**本プロジェクトでの実装**:
- **定期タスク生成ジョブ**: 毎分実行。生成時刻に到達したテンプレートからタスクを自動生成
- **期限超過通知ジョブ**: 毎日 00:05 実行。期限超過タスクの担当者に通知を生成

**実装**: Hangfire の RecurringJob を使用して SQL Server に永続化

**関連用語**:
- [Hangfire](#hangfire)
- [定期タスク](#定期タスク)

**英語表記**: Background Job

---

### DTO（Data Transfer Object）

**定義**: レイヤー間でデータを受け渡すための専用オブジェクト。エンティティを直接公開しない。

**本プロジェクトでの用途**: API のリクエスト・レスポンスに使用。エンティティの全フィールドを公開せず、必要な情報だけを受け渡すことでセキュリティと保守性を向上させる。

**配置**: `TaskManagement.Application/DTOs/`

**例**:
- `CreateTaskRequest`: タスク作成の入力データ
- `TaskResponse`: タスク取得の出力データ

**英語表記**: Data Transfer Object (DTO)

---

### マイグレーション

**定義**: データベーススキーマの変更履歴を管理し、バージョンごとに適用・ロールバックできる仕組み。

**本プロジェクトでの用途**: EF Core の Code First マイグレーションを使用。エンティティクラスの変更を `dotnet ef migrations add` でマイグレーションファイルとして記録し、`dotnet ef database update` で適用する。

**配置**: `TaskManagement.Infrastructure/Data/Migrations/`

**英語表記**: Migration

---

### Cookie 認証

**定義**: HTTP-only Cookie を使用したセッション管理方式。

**本プロジェクトでの適用**: ログイン成功時に ASP.NET Core がセッションチケットを HTTP-only Cookie として発行。Angular は `withCredentials: true` で Cookie を自動送信。XSS 対策として JavaScript から Cookie にアクセスできない。

**関連用語**:
- [SPA](#spa)

---

## 略語・頭字語

### SPA

**正式名称**: Single Page Application

**意味**: 最初のページロード後はページ全体を再読み込みせず、JavaScript で動的にコンテンツを更新する Web アプリケーション形式。

**本プロジェクトでの使用**: Angular で実装されるフロントエンドが SPA として動作する。

---

### ORM

**正式名称**: Object-Relational Mapper

**意味**: オブジェクト指向言語のクラスとリレーショナルデータベースのテーブルを対応付け、SQL を書かずにデータ操作を可能にするライブラリ。

**本プロジェクトでの使用**: EF Core が ORM として機能する。

---

### CRUD

**正式名称**: Create / Read / Update / Delete

**意味**: データの基本操作の4種類。

**本プロジェクトでの使用**: タスク・ステータス・ラベル・ユーザー等の管理 API において CRUD 操作を提供する。

---

### DI

**正式名称**: Dependency Injection（依存性の注入）

**意味**: クラスの依存オブジェクトを外部から注入するデザインパターン。テスト時にモックを注入しやすくなる。

**本プロジェクトでの使用**: ASP.NET Core の組み込み DI コンテナを使用。`Program.cs` でサービスを登録し、コンストラクター経由で注入する。

---

### IIS

→ [技術用語 IIS](#iisinternet-information-services) を参照

---

### API

**正式名称**: Application Programming Interface

**意味**: ソフトウェア間の通信仕様・インターフェース。

**本プロジェクトでの使用**: Angular フロントエンドと ASP.NET Core バックエンドは REST API（JSON over HTTPS）で通信する。

## データモデル用語

### TaskItem（タスク）

**定義**: システムの中心エンティティ。ユーザーの作業を管理する。

**主要フィールド**:
- `Id`: 主キー（自動採番）
- `Title`: タスクタイトル（必須・最大200文字）
- `StatusId`: ステータスへの外部キー（必須）
- `Priority`: 優先度（High / Medium / Low）
- `DueDate`: 期限日（任意）
- `ParentTaskId`: 親タスクへの外部キー（サブタスクの場合に設定）
- `IsRecurring`: 定期タスクフラグ
- `CreatedByUserId`: 作成者

**関連エンティティ**: TaskStatus、TaskAssignee、TaskLabel、TaskShare、RecurringTemplate

---

### TaskStatus（ステータス）

**定義**: タスクに設定できるステータスのマスタデータ。管理者が管理する。

**主要フィールド**:
- `Id`: 主キー
- `Name`: ステータス名
- `Color`: バッジ色（HEX カラーコード）
- `DisplayOrder`: 表示順
- `IsActive`: 論理削除フラグ

---

### RecurringTemplate（定期タスクテンプレート）

**定義**: 定期タスクを自動生成するための設定を保持するエンティティ。

**主要フィールド**:
- `Frequency`: 繰り返し頻度（Daily / Weekly / Monthly）
- `WeekDays`: 週次の場合の曜日（0=日〜6=土）
- `DayOfMonth`: 月次の場合の日
- `ExcludeWeekends`: 土日除外フラグ
- `ExcludeHolidays`: 祝日除外フラグ
- `GenerationTime`: タスクを生成する時刻

---

## エラー・例外

### NotFoundException

**クラス名**: `NotFoundException`

**発生条件**: 指定された ID のリソース（タスク・ユーザー等）がデータベースに存在しない場合。

**HTTP ステータス**: 404 Not Found

**対処方法**:
- ユーザー: 「タスクが見つかりませんでした」のメッセージを確認し、URL や操作を見直す
- 開発者: 削除済みのリソースへのアクセスか確認。論理削除されたデータへのクエリを見直す

**使用例**:
```csharp
var task = await _taskRepository.GetByIdAsync(id)
    ?? throw new NotFoundException("タスク", id);
```

---

### ForbiddenException

**クラス名**: `ForbiddenException`

**発生条件**: 認証済みユーザーが閲覧権限を持たないタスクへアクセスしようとした場合（[公開範囲](#公開範囲)の制限）。

**HTTP ステータス**: 403 Forbidden

**対処方法**:
- ユーザー: 「このタスクを閲覧する権限がありません」のメッセージを確認。タスク所有者に共有を依頼する
- 開発者: サービス層の共有範囲チェックロジックを確認する

---

## ステアリングファイル

**定義**: 短期的なタスク管理のために作成される一時的なドキュメント群。

**説明**: 機能追加や設計変更を行う際に `.steering/{YYYYMMDD}-{作業名}/` に作成する。作業完了後は削除またはアーカイブする（`.gitignore` に追加されているため Git には含まれない）。

**ディレクトリ構造**:
```
.steering/
└── 20260501-add-subtask-feature/
    ├── requirements.md    # 今回の作業の要求内容
    ├── design.md          # 変更内容の設計
    └── tasklist.md        # タスクリスト
```

**英語表記**: Steering File
