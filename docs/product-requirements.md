# プロダクト要求定義書 (Product Requirements Document)

## プロダクト概要

### 名称
**TaskApp** - チーム向けタスク管理Webアプリケーション

### プロダクトコンセプト
- **シンプルで使いやすいチーム共有**: Redmineの設定の複雑さを排除し、必要最小限の入力で素早くタスクを登録・共有できる
- **チームの作業状況の可視化**: 誰が何のタスクを担当・消化中かをダッシュボードで一目把握できる
- **社内完結の安全な管理**: イントラネット環境に閉じた運用で外部ツールへの依存なしにチームのタスクを一元管理する

### プロダクトビジョン
社内のセキュリティ制約のもとで外部ツールを導入できないチームが、チームメンバーの担当タスクを透明化し作業の重複・抜け漏れをなくすためのWebアプリを提供する。
Redmineを参考にしつつも設定の複雑さを大幅に削減し、日常業務のなかで自然に使い続けられる軽量なUXを実現する。
定期タスクの自動生成により、日常点検・清掃などの繰り返し業務の手動登録コストをゼロにする。

### 目的
- チームメンバーの担当タスクをリアルタイムで可視化し、属人化・情報の分散を解消する
- セキュリティ・イントラネット制約下でも運用できる自社開発ツールを提供する
- 自主開発を通じて開発チームのスキルアップを促進する
- 将来的な全社展開に向けた拡張性を確保する

---

## ターゲットユーザー

### プライマリーペルソナ: チームメンバー（一般ユーザー）
- 5人程度のチームに所属するビジネス職・技術職スタッフ
- タスク管理ツールに慣れていないメンバーも含む（過剰な設定画面は使わない）
- 現在の課題: 誰が何を担当しているか把握できず、報告・確認のコミュニケーションコストが高い
- 期待する解決策: 最小限の入力でタスクを登録でき、チームの進捗をひと目で確認できること
- 1日のワークフロー: 朝にダッシュボードで自分のタスクと期限を確認し、作業完了後にステータスを更新する

### セカンダリーペルソナ: 管理者
- チームリーダーまたはシステム管理者
- アカウント発行・ステータス定義・タグ管理など運用設定を担当
- 現在の課題: チームの作業負荷と進捗状況を一覧できる場所がない
- 期待する解決策: タスクの割り当て状況・ステータス推移を管理画面から確認・操作できること

## 成功指標 (KPI)

### プライマリーKPI
- アクティブユーザー率: リリース後1ヶ月以内に対象チーム全員（5人）が週3回以上ログインして使用
- タスク登録数: 1ユーザーあたり週5件以上のタスクをアプリ内で管理（従来の口頭・メモ依存からの移行）
- タスク完了率: 登録タスクの70%以上が「完了」ステータスに到達（タスクの消化追跡が機能していること）

### セカンダリーKPI
- タスク登録時間: 1タスクの新規登録が30秒以内に完了できる（UXの軽量さ）
- 定期タスク自動生成の稼働率: 設定済み定期タスクが予定時刻から±5分以内に生成される
- 全社展開への準備: リリース後6ヶ月以内に全社展開のためのスケールアップ方針を確定

## 機能要件

### コア機能 (MVP)

#### 1. タスク管理

**ユーザーストーリー**:
チームメンバーとして、作業内容をチームと共有するために、タスクを素早く登録・編集・確認したい

**受け入れ条件**:
- [ ] タイトルとステータスのみ入力すれば30秒以内にタスクを登録できる
- [ ] 説明・担当者（複数人）・期限日・優先度（高/中/低）・ラベル・親タスクはオプションで後から設定できる
- [ ] タスクの編集・削除ができる
- [ ] タスクにサブタスク（子タスク）を追加し、チェックリスト形式で進捗管理できる
- [ ] タスク詳細画面で全属性の確認・編集ができる

**優先度**: P0（必須）

---

#### 2. ダッシュボード

**ユーザーストーリー**:
チームメンバーとして、今日やるべき作業とチームの状況を把握するために、ログイン後すぐに概況を確認したい

**受け入れ条件**:
- [ ] ログイン後の初期画面に「マイタスク」（自分に割り当てられたタスク一覧）が表示される
- [ ] 「チーム共有タスク」セクションで、共有されているタスクと担当者が一覧表示される
- [ ] 期限超過タスクが視覚的に区別されて表示される（色分けなど）
- [ ] 定期タスクはダッシュボードでデフォルト非表示（フィルターで切り替え可能）

**優先度**: P0（必須）

---

#### 3. タスク一覧・検索・フィルター

**ユーザーストーリー**:
チームメンバーとして、必要なタスクを素早く見つけるために、条件を組み合わせてタスクを絞り込みたい

**受け入れ条件**:
- [ ] 担当者・期限日・ステータス・優先度・ラベルの組み合わせでフィルタリングできる
- [ ] フリーワード検索（タイトル・説明文に対して）ができる
- [ ] 定期タスクのフィルター切り替えができる（デフォルト非表示）
- [ ] フィルター条件を保持したままページ遷移できる（URLパラメーター管理）

**優先度**: P0（必須）

---

#### 4. ステータス管理

**ユーザーストーリー**:
管理者として、チーム全体のワークフローに合わせたステータスを定義するために、アプリ全体で使用するステータスを設定・管理したい

**受け入れ条件**:
- [ ] 管理者がステータス名・表示順・色（バッジ色）を設定できる
- [ ] デフォルトで「未着手・進行中・レビュー中・保留・完了」が初期設定されている
- [ ] ステータスの追加・編集・論理削除（使用中のタスクに影響しない）ができる
- [ ] 全プロジェクト・全タスクで同一のステータスセットを使用する

**優先度**: P0（必須）

---

#### 5. ラベル・タグ管理

**ユーザーストーリー**:
管理者として、タグの表記ゆれを防ぐために、公式タグを定義・管理したい。
チームメンバーとして、新しいタグが必要な場合に管理者へリクエストしたい

**受け入れ条件**:
- [ ] 管理者がタグ名・色を設定・管理できる
- [ ] ユーザーはタスクに公式タグのみを付与できる（自由入力不可）
- [ ] ユーザーは管理者に新規タグ追加をリクエストできる（リクエスト機能）
- [ ] タグの表記ゆれ・重複を防ぐため、タグ名の重複チェックをシステムが行う

**優先度**: P0（必須）

---

#### 6. タスクの共有・公開範囲設定

**ユーザーストーリー**:
チームメンバーとして、関係者だけにタスクを共有するために、タスクの公開範囲を設定したい

**受け入れ条件**:
- [ ] タスク単位で共有するメンバーを選択できる（個人単位）
- [ ] サブタスクは親タスクの公開範囲を自動継承する（個別設定不要）
- [ ] 公開範囲外のユーザーからはタスクが見えない

**優先度**: P0（必須）

---

#### 7. タスクの担当者割り当て

**ユーザーストーリー**:
チームメンバーとして、作業を適切に分担するために、タスクを複数のメンバーへ割り当てたい

**受け入れ条件**:
- [ ] タスクに複数ユーザーを担当者として設定できる
- [ ] 他ユーザーのタスクを自分に引き取ったり、他のユーザーに振り直せる
- [ ] 担当者が変更されたとき、新しい担当者にアプリ内通知が送られる

**優先度**: P0（必須）

---

#### 8. 定期タスク（繰り返しタスク）

**ユーザーストーリー**:
チームメンバーとして、日常的な繰り返し業務を毎回手動登録しなくて済むように、定期タスクをテンプレートから自動生成したい

**受け入れ条件**:
- [ ] タスクを「定期タスク」として登録し、タイトル・説明・担当者・優先度・ラベル・共有設定をテンプレートとして保存できる
- [ ] 繰り返し頻度を設定できる（毎日 / 毎週◯曜日 / 毎月◯日）
- [ ] 除外日を設定できる（土日除く / 祝日除く）。祝日は管理者が別途設定する
- [ ] 生成時刻を設定できる（例: 毎朝8:00）
- [ ] Hangfire または Quartz.NET のバックグラウンドジョブで自動生成される
- [ ] タスク一覧・ダッシュボードで定期タスクはデフォルト非表示、フィルターで切り替え可能

**優先度**: P0（必須）

---

#### 9. ユーザー管理・認証

**ユーザーストーリー**:
管理者として、セキュリティを確保しながらチームメンバーのアクセスを管理するために、アカウントの発行・管理を一元的に行いたい

**受け入れ条件**:
- [ ] 管理者がID・パスワードでアカウントを作成できる（自己登録は不可）
- [ ] 各ユーザーは自分のプロフィール（表示名など）を編集できる
- [ ] 各ユーザーは自分のパスワードを変更できる
- [ ] 管理者はアカウントの有効化・無効化ができる
- [ ] ロールは最低限「管理者」「一般ユーザー」の2種類

**優先度**: P0（必須）

---

#### 10. アプリ内通知

**ユーザーストーリー**:
チームメンバーとして、自分に関係するタスクの変化に気づくために、アプリ内で通知を受け取りたい

**受け入れ条件**:
- [ ] 自分へのタスク割り当て時に通知が届く
- [ ] 担当タスクの期限超過時に通知が届く
- [ ] 通知一覧画面から既読・未読の確認・管理ができる
- [ ] メール・外部サービス連携は対象外（アプリ内通知のみ）

**優先度**: P0（必須）

---

### 将来的な機能 (Post-MVP)

#### ガントチャート
タスクのスケジュールを時系列で視覚化する。  
**優先度**: P2（できれば）

#### Wiki
プロジェクト・チームに関するドキュメントをアプリ内で管理する。  
**優先度**: P2（できれば）

#### メール・Slack通知
タスク割り当て・期限超過時にメールまたはSlack通知を送信する。  
**優先度**: P2（できれば）

#### 部署・グループ単位の共有設定
タスクの公開範囲を個人ではなく部署・グループ単位で設定できるようにする。  
**優先度**: P2（できれば）

#### プロジェクト単位のステータスカスタマイズ
プロジェクトごとに独自のステータスセットを設定できるようにする（現在はアプリ全体で共通）。  
**優先度**: P2（できれば）

## 非機能要件

### パフォーマンス
- ページ初期表示（ダッシュボード・一覧）: ネットワーク遅延を除き2秒以内
- タスク登録・更新のAPIレスポンス: 500ms以内
- フィルター・検索結果の表示: 1,000件まで3秒以内

### ユーザビリティ
- タスクの新規登録がタイトル入力のみで30秒以内に完了できる
- ツールチップ・プレースホルダーで操作を自己説明し、マニュアルなしに基本操作を習得できる
- Angular Material準拠のUIで、社内のWindowsデスクトップブラウザ（Chrome / Edge最新版）で正常動作する

### 信頼性
- 定期タスクの自動生成: スケジュール時刻から±5分以内に実行される
- トランザクション管理により、タスク登録・更新時のデータ損失をゼロにする
- 障害時にエラーログを記録し、管理者が原因を特定できる

### セキュリティ
- すべての通信はHTTPS（TLS 1.2以上）で暗号化する
- パスワードはbcryptなどの安全なアルゴリズムでハッシュ化して保存する
- セッション管理にはHTTP-only Cookieを使用しXSS対策を行う
- 認可チェック: 公開範囲外のタスクにはAPIレベルでアクセス拒否する
- 管理者機能のエンドポイントはロールベースで保護する

### スケーラビリティ
- 初期: 5ユーザー / 将来: 100ユーザー以上を想定した設計（DB・アプリサーバーの水平スケールが可能なアーキテクチャ）
- SQL Serverを使用し、インデックス設計によりタスク件数が10,000件を超えても一覧表示のパフォーマンスを維持する

### 運用・保守
- Windows Server + IIS 環境にデプロイ可能
- Hangfire または Quartz.NET によるバックグラウンドジョブの管理UIを提供する
- ログ出力（アプリケーションログ・エラーログ）をファイルまたはイベントログへ書き出す

---

## スコープ外

明示的にスコープ外とする項目:
- ガントチャート
- Wiki機能
- メール・Slack等の外部通知連携
- 部署・グループ単位の共有設定
- プロジェクト単位のステータスカスタマイズ
- ユーザーの自己登録機能
- モバイルアプリ（iOS / Android）
- 外部サービスとのAPI連携（Jira / Asana等）
